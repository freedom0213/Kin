# Kin 两台 Android 真机测试手册

## 1. 测试目标

这份手册用于在两台 Android 手机上验收 Kin Development APK，重点覆盖：

- 登录、在线状态和账号数据隔离；
- Android 物理 NFC“碰一碰”加好友与配对码备用流程；
- 双方核对名片并分别确认后才建立好友关系；
- 文字、表情、语音消息及送达、已读状态；
- 前台语音通话、接听、拒接、挂断和网络恢复；
- Graphite Flow 深色主题、弹窗、滚动和键盘布局。

系统后台推送、跨公网通话和 iOS NFC 不属于本轮局域网验收范围。

## 2. 物理“碰一碰”的实现边界

本版采用 Android HCE + IsoDep Reader Mode：

1. 手机 A 点击“发起碰一碰”，Kin 创建一个最长约 120 秒有效的后端临时配对凭证，并通过 HCE 将手机模拟成一张 Kin 专用 NFC 卡。
2. 手机 B 点击“接收附近设备”，进入 IsoDep Reader Mode。
3. 两台手机背部 NFC 天线区域靠近，B 从 A 读取临时凭证。
4. B 使用凭证加入后端配对会话，两台手机分别展示对方名片。
5. A、B 都点击“确认是本人”后，后端才正式建立好友关系。

NFC 只传递短期凭证，不直接添加好友，也不会通过 NFC 传输聊天记录、密码、私钥或长期身份凭据。配对会话是否有效、是否完成以及好友关系均以后端为准。

### 平台和设备限制

| 场景 | 发起碰一碰 | 接收附近设备 | 备用方案 |
| --- | --- | --- | --- |
| Android，支持 NFC 和 HCE | 支持 | 支持 | 配对码 |
| Android，支持 NFC 但不支持 HCE | 不支持发起 | 通常可接收 | 配对码，或让另一台 HCE 手机发起 |
| Android，不支持 NFC | 不支持 | 不支持 | 配对码 |
| iPhone / iOS | 本版本不支持 | 本版本不支持 | 配对码 |
| Expo Go 或旧 APK | 不包含 Kin HCE 原生模块 | 功能可能不完整 | 安装新 Development APK 或使用配对码 |

注意：Android 厂商对 HCE、后台限制和 NFC 天线位置的实现存在差异，不能保证所有型号表现完全一致。首版应至少在两个不同品牌或型号上交叉测试。

## 3. 测试前准备

### 3.1 设备与系统状态

- 两台 Android 手机均安装本次重新构建的同一版本 Development APK；旧 APK 不包含新增 HCE 原生模块。
- 两台手机都打开 NFC，并保持屏幕点亮、设备解锁、Kin 位于前台。
- 发起方必须支持 HCE；接收方必须支持 NFC Reader Mode。
- 暂时取下金属、磁吸或特别厚的手机壳，避免阻挡 NFC 信号。
- 查找两台手机的 NFC 天线位置。常见位置在背部上方或摄像头附近，但以手机说明书为准。
- 两台手机不要长时间平放叠压；先缓慢移动寻找感应点，识别成功后即可分开。

### 3.2 局域网

1. 电脑和两台手机连接同一个普通 Wi-Fi。
2. 关闭手机的“智能切换移动数据”“双通道加速”等功能。
3. 不要使用访客 Wi-Fi；它可能启用 AP 隔离，导致设备无法访问电脑。
4. 在 PowerShell 运行 `ipconfig`，找到当前 Wi-Fi 网卡的 IPv4，例如 `192.168.1.20`。

手机不能使用以下地址访问电脑后端：

- `127.0.0.1`：在手机上表示手机自己；
- `10.0.2.2`：只适用于 Android 模拟器；
- VPN、虚拟机或代理软件生成的虚拟网卡地址。

### 3.3 配置后端地址

在 `mobile/.env.local` 中设置：

```env
EXPO_PUBLIC_KIN_API_BASE=http://192.168.1.20:8000
```

将示例 IP 换成电脑当前 Wi-Fi IPv4。`.env.local` 包含个人局域网配置，不应提交 Git。修改环境变量后需要重新启动 Metro；若该地址被写入构建产物，还需要重新构建 APK。

### 3.4 启动后端

在项目根目录运行：

```powershell
python -m uvicorn main:app --app-dir backend --host 0.0.0.0 --port 8000
```

先在电脑浏览器访问：

```text
http://127.0.0.1:8000/api/health
```

再在两台手机浏览器访问：

```text
http://电脑局域网IP:8000/api/health
```

两台手机都看到健康状态后再继续。如果电脑能访问而手机不能访问，应检查 Windows 防火墙是否允许 Python/Uvicorn 在“专用网络”通信，以及路由器是否开启 AP 隔离；不要为了测试直接关闭全部防火墙。

### 3.5 启动 Metro

Development APK 需要 Metro 提供 JavaScript bundle。在 `mobile` 目录运行：

```powershell
npx expo start --dev-client --lan --port 4182
```

这条命令不是启动后端。它只为 Development APK 提供前端 JavaScript、资源和热更新。终端必须保持运行，两台手机应连接同一个 Metro 地址。

## 5. 推荐验收顺序

### A. 启动、登录与主题

1. 启动两台手机上的 Kin，确认不再出现白色圆环启动页。
2. 检查登录、注册、会话、通讯录、我的、聊天和弹窗均为 Graphite Flow 高级黑主题。
3. 分别登录两个不同账号，确认头像、好友、会话和聊天记录不会串号。
4. 检查密码文字可辨认，显隐按钮不会清空输入内容。

### B. 物理 NFC 碰一碰

1. 确认双方尚未互为好友，并都能访问后端。
2. 手机 A 打开“添加好友”，点击“发起碰一碰”。
3. A 应出现等待弹窗和临时配对码；配对码在 NFC 失败时始终可用。
4. 手机 B 打开同一页面，点击“接收附近设备”。
5. 保持两台手机解锁、亮屏、Kin 前台，将背部 NFC 天线区域缓慢靠近。
6. 感应成功后分开手机，检查双方都出现对方头像、背景、昵称和用户名。
7. 只让 A 点击“确认是本人”，确认此时仍未成为好友，A 显示等待对方确认。
8. 再让 B 确认，检查双方同时成为好友并可进入聊天。
9. 返回通讯录，确认新好友只出现一次；重新登录后关系仍存在。

### C. NFC 失败与配对码降级

逐项验证以下情况均给出明确说明，并能改用配对码：

- 一方关闭 NFC；
- 接收方等待超时；
- 两台手机未对准 NFC 天线；
- 发起方手机不支持 HCE；
- 使用未包含 HCE 模块的旧 APK；
- 临时会话超过有效期；
- 双方 APK 协议版本不一致；
- 任一方取消，另一方不能继续确认旧会话。

配对码流程：A 发起后展示配对码，B 展开“无法碰一碰？使用配对码”，输入完整配对码并加入，之后仍必须双方核对名片并分别确认。

### D. 消息

1. A 向 B 连续发送短文字、长文字、表情和多条消息。
2. 输入内容较短时，输入框与语音键、发送键等高；多行内容时输入框逐步增高但不挤出操作区。
3. 新消息应立即出现在当前聊天页底部，不应只更新最近会话摘要。
4. B 收到消息后检查送达状态；B 打开聊天后检查已读状态。
5. 双方互发语音消息，检查录制、取消、时长、播放、暂停和滚动位置。
6. 检查“仅你和对方可读取”常驻聊天区域顶部，背景一致且不会导致页面跳动。
7. 消息较多时检查滚动条细小、贴合暗色背景，并能正确滚动到最新消息。

### E. 在线、离线与同步

1. 两台手机前台在线时，双方显示 Online。
2. 将 B 切到后台或断网，确认状态最终变为 Offline，但离线本身不等于缺少公钥。
3. B 离线期间由 A 发消息，B 恢复连接后应同步消息。
4. 在同一手机切换不同账号，确认聊天记录按账号隔离。

### F. 语音通话

1. 检查双方麦克风权限和系统媒体音量。
2. A 呼叫 B，B 前台出现来电卡片。
3. B 接听后检查计时、双方声音和挂断同步。
4. 再次呼叫并拒接，A 应显示对方拒接。
5. 通话中短暂关闭再恢复网络，提示应明确区分通话网络恢复和普通服务器重连。
6. 两台手机距离很近时建议佩戴耳机或放在不同房间，避免声学回授被误判为通话故障。

### G. 我的页面与弹窗回归

1. “我的名片、个人资料、通知与状态、账户与安全、外观与体验、帮助与法律”分别进入独立页面。
2. 检查名片背景比例、头像衔接处无异常白色分割层。
3. 所有确认、提示和 Bottom Sheet 关闭时不闪现上一个弹窗。
4. 拖动 Bottom Sheet 到关闭阈值后应真正关闭；松开鼠标或手指后不得继续跟随。

## 7. 常见问题

### 手机能够打开 App，但无法登录

Development APK 只连接到了 Metro，不代表已连接后端。确认 Uvicorn 仍在运行、`.env.local` 使用电脑局域网 IP，并用手机浏览器访问 `/api/health`。

### 页面提示“当前 APK 不含 HCE 模块”

当前安装包是在新增原生模块之前构建的。必须重新制作并安装 Development APK；仅刷新 Metro 无法向旧 APK 添加原生代码。

### 一台手机能接收但不能发起

该设备可能支持普通 NFC Reader Mode，但不支持 Host Card Emulation。让另一台支持 HCE 的手机作为发起方，或使用配对码。

### 两台手机始终感应不到

确认双方已按下对应按钮，屏幕点亮且解锁，Kin 位于前台；取下金属或磁吸手机壳，并移动背部不同区域寻找天线重叠位置。不要把两个屏幕面对面贴合。

### 已经感应，但没有成为好友

这是预期的安全流程。物理感应只加入临时配对会话，双方仍需核对名片并各自点击确认。任一方未确认、取消或会话过期，都不会建立好友关系。

### 聊天正常但语音通话无声音

检查麦克风权限、媒体音量和蓝牙音频路由。当前 WebRTC 只有 STUN、没有 TURN，复杂 NAT、校园网、公司网或跨移动网络时可能无法建立媒体连接；这与 NFC 无关。

## 8. 本轮完成标准

- 新 Development APK 在至少两台 Android 真机安装并启动；
- 至少一个方向的 HCE 发起 + IsoDep 接收成功；
- 若两台手机都支持 HCE，角色互换也成功；
- NFC 失败时配对码始终可用；
- 物理感应后必须双方确认，不能绕过后端直接加好友；
- 核心消息、在线状态、语音和页面回归测试无阻断问题；
- 测试结果记录设备型号、Android 版本、APK 构建编号和复现步骤。

通过本地自动检查只说明代码、协议和配置一致；Android 原生模块最终是否兼容具体手机，必须以重新构建 APK 后的双机真机结果为准。
