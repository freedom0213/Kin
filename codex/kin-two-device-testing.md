# Kin 两台 Android 真机局域网联调

## 目的

先在同一局域网内验证 Kin 的核心链路：

- 两个账号登录和保持在线
- 文字消息、语音消息、送达与已读状态
- 前台来电卡片、接听、拒接和通话
- 一台手机临时离线后的消息同步

后台系统通知需要后续完成 EAS projectId、推送凭据和开发版 APK 构建后再测试。

## 一、准备网络

1. 电脑和两台 Android 手机连接同一个 Wi-Fi。
2. 关闭手机的“随机切换移动数据”或类似网络加速功能。
3. 如果电脑开启了代理软件，允许局域网连接，或暂时关闭代理的 TUN/防火墙接管。
4. 在 PowerShell 运行：

       ipconfig

5. 找到当前 Wi-Fi 网卡的 IPv4，例如 192.168.1.20。

不要使用以下地址：

- 127.0.0.1：在手机上代表手机自己。
- 10.0.2.2：只适用于 Android 模拟器。
- VPN、虚拟机、代理软件生成的虚拟网卡地址。

## 二、配置手机访问地址

在 mobile 目录复制环境变量模板：

    Copy-Item .env.example .env.local

编辑 .env.local：

    EXPO_PUBLIC_KIN_API_BASE=http://192.168.1.20:8000

将示例 IP 换成电脑当前的 Wi-Fi IPv4。.env.local 已被 Git 忽略，不会上传个人网络地址。

## 三、启动本地后端

在项目根目录运行：

    cd backend
    python -m uvicorn main:app --reload --host 0.0.0.0 --port 8000

先在电脑浏览器访问：

    http://127.0.0.1:8000/api/health

然后在两台手机浏览器分别访问：

    http://电脑局域网IP:8000/api/health

两台手机都看到 status 为 ok 后，才继续安装和启动 Kin。

如果电脑能访问、手机不能访问，通常是 Windows 防火墙或 Wi-Fi 的 AP 隔离。只允许 Python/Uvicorn 在“专用网络”通信，不要直接关闭全部防火墙。

## 四、安装 Kin 开发版本

Kin 使用 NFC 和 react-native-webrtc 原生模块，Expo Go 无法完整运行。需要以下任一方式：

### 推荐：EAS Development Build

用 EAS 构建一个 Android 开发 APK，两台手机安装同一个 APK。优点是无需在本机安装 Android SDK，后续也能继续测试系统推送。

### 本地 Android 构建

需要安装 Android Studio、Android SDK、ADB，并通过 USB 分别安装。当前开发电脑尚未检测到 Android SDK，因此暂不采用。

## 五、启动 Metro

开发 APK 安装后，在 mobile 目录运行：

    npx expo start --dev-client --lan

确保 Metro 显示的地址也是电脑局域网地址，而不是 VPN 虚拟网卡地址。

## 六、两台手机测试顺序

将手机分别称为 A 和 B。

1. A 注册并登录账号 kin_test_a。
2. B 注册并登录账号 kin_test_b。
3. 通过 NFC 碰一碰或开发阶段已有的配对入口互加好友。
4. 保持两台手机前台运行，确认双方显示 Online。
5. A 向 B 发送文字，检查：
   - A 先显示发送状态。
   - B 出现消息。
   - B 保存成功后 A 显示送达状态。
   - B 打开对话后 A 显示已读状态。
6. B 向 A 发送语音消息，检查录制、播放和时长。
7. A 向 B 发起语音通话，检查：
   - B 当前页面顶部出现磨砂来电卡片。
   - 点击接听后仍停留当前页面，卡片切换为通话中和计时。
   - 双方可以听到声音。
   - 挂断后双方状态都恢复。
8. 再次呼叫并点击拒绝，确认 A 显示对方拒接。
9. 将 B 切到后台后由 A 发消息，检查 B 回到 Kin 后消息同步。
10. 通话中短暂关闭 B 的 Wi-Fi，再恢复，确认提示明确区分“通话网络恢复”和普通服务器重连。

## 七、常见问题

### 两台手机都无法登录

优先检查 .env.local、后端是否监听 0.0.0.0，以及手机浏览器能否访问健康检查。

### 聊天正常但语音通话没有声音

检查麦克风权限、系统媒体音量和是否连接蓝牙耳机。两台手机靠得很近时会产生回声，建议佩戴耳机或放在不同房间测试。

### 同一 Wi-Fi 仍无法互通

访客 Wi-Fi 常开启 AP 隔离。将三台设备连接普通家庭网络，或使用一台手机开热点让电脑和另一台手机接入。

### 通话只能在同一 Wi-Fi 成功

当前 WebRTC 只有 STUN，没有 TURN。复杂 NAT、校园网、公司网或移动网络下可能无法建立媒体连接，后续部署阶段需要增加 TURN 服务。
